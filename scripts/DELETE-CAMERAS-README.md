# Delete All Cameras and Branch Edges Scripts

This directory contains scripts to delete all cameras and edge agents (branch edges) from the database.

## ⚠️ WARNING

**These scripts perform irreversible operations!** They will:

- Delete all cameras and their resource nodes
- Delete all edge agents (branch edges)
- Delete all camera discoveries
- Unlink all device identities
- Delete all recording jobs, segments, and live sessions
- Delete all analytics alerts related to cameras
- Delete all incident camera links
- Delete all camera access requests and specifications
- Delete all edge activation tokens, scan jobs, commands, and managed tunnels

**There is no way to recover this data after deletion.**

## Available Scripts

### 1. TypeScript Version (`delete-all-cameras-and-edges.ts`)

Requires TypeScript compilation.

**Usage:**
```bash
# From the backend directory
npx tsx scripts/delete-all-cameras-and-edges.ts
```

### 2. JavaScript ES Module Version (`delete-all-cameras-and-edges.mjs`)

Can be run directly with Node.js (recommended).

**Usage:**
```bash
# From the root directory
node scripts/delete-all-cameras-and-edges.mjs
```

## Prerequisites

1. **Environment Variables**: Ensure you have either `DATABASE_URL` or `DIRECT_URL` set in your environment or `.env` file:
   ```bash
   DATABASE_URL=postgresql://user:password@host:5432/database
   ```

2. **Database Access**: You must have appropriate permissions to delete data from the database.

3. **Node.js**: Node.js 16+ is required.

## How It Works

### Step-by-Step Process

The script performs deletion in the following order to respect foreign key constraints:

1. **Camera Access Requests** - Deletes all pending/approved camera access requests
2. **Camera Specifications** - Deletes detailed camera specification records
3. **Incident Cameras** - Removes camera links from incidents
4. **Recording Segments** - Deletes all video recording segments for cameras
5. **Analytics Alerts** - Removes all analytics alerts generated by cameras
6. **Live Sessions** - Deletes all active/past live streaming sessions
7. **Recording Jobs** - Removes all recording job configurations
8. **Camera Discoveries** - Deletes pending camera discovery records
9. **Cameras** - Deletes the main camera records
10. **Camera Resource Nodes** - Removes camera nodes from the resource hierarchy
11. **Device Identities** - Unlinks device identities from deleted cameras
12. **Edge Commands** - Deletes all commands sent to edge agents
13. **Edge Scan Jobs** - Removes all network scan job records
14. **Edge Managed Tunnels** - Deletes tunnel configurations
15. **Edge Activation Tokens** - Removes all activation tokens
16. **Edge Agents** - Deletes all edge agent (branch edge) records

### Safety Features

- **Confirmation Prompt**: The script requires you to type "DELETE ALL" before proceeding
- **Current State Display**: Shows counts of all records before deletion
- **Transaction-Based**: All deletions happen in a single database transaction
- **Automatic Rollback**: If any error occurs, all changes are rolled back
- **Detailed Logging**: Shows progress for each deletion step
- **Summary Report**: Displays final counts of all deleted records

## Troubleshooting

### "DATABASE_URL environment variable is required"

Make sure you have `DATABASE_URL` or `DIRECT_URL` set in your environment:

```bash
# Load from .env file
export $(cat .env | xargs)

# Or set directly
export DATABASE_URL="postgresql://..."
```

### Foreign Key Constraint Errors

The script is designed to handle foreign key constraints by deleting in the correct order. If you encounter constraint errors, it may indicate:

- Custom tables referencing cameras/edge agents not handled by the script
- Database schema changes
- Concurrent modifications to the database

### Transaction Timeout

For very large datasets (millions of records), the transaction might timeout. Consider:

- Increasing the database `statement_timeout` setting
- Running the script during off-peak hours
- Modifying the script to delete in batches

## Recovery

**There is no automated recovery mechanism.** Once deleted, the data is permanently lost.

To restore:
1. Restore from a database backup taken before running the script
2. Re-run camera discovery scans
3. Manually re-add cameras and edge agents
