# Camera Discovery Architecture - Complete Flow

## Overview

This document explains the complete end-to-end flow of camera discovery in the system.

## Components

### 1. Edge Agent / Installer (.BAT file)
- **Location**: Generated by `src/routes/edge-agent-package.routes.ts` (line 251+)
- **Purpose**: Scans network for cameras using ONVIF/RTSP
- **Output**: POSTs discovered camera data to backend API

### 2. Backend API Endpoint
- **Route**: `POST /v1/branches/:branchId/cameras/discovered`
- **File**: `src/app.ts` (line 1404+)
- **Handler**: Validates payload and calls `store.createDiscovery()`

### 3. Database Repository
- **File**: `src/database/edge-agent-repository.ts`
- **Method**: `createDiscovery()` (line 446+)
- **Logic**:
  - Resolves device identity (MAC, serial, IP)
  - Inserts into `camera_discoveries` table
  - Sets status to `"pending"` for user review
  - Handles conflicts (duplicate discoveries)

### 4. Database Tables

#### `camera_discoveries`
```sql
CREATE TABLE camera_discoveries (
  id UUID PRIMARY KEY,
  branch_node_id UUID REFERENCES resource_nodes(id),
  device_identity_id UUID REFERENCES device_identities(id),
  edge_agent_id UUID,
  discovery_method discovery_method_enum,
  manufacturer TEXT,
  vendor vendor_enum,
  model TEXT,
  ip_address INET,
  mac_address MACADDR,
  onvif_port INT,
  rtsp_port INT,
  profiles JSONB,
  capabilities JSONB,
  status discovery_status, -- 'pending' | 'approved' | 'rejected'
  discovered_at TIMESTAMP,
  -- ... more fields
  UNIQUE (branch_node_id, device_identity_id)
);
```

#### `device_identities`
```sql
CREATE TABLE device_identities (
  id UUID PRIMARY KEY,
  tenant_id UUID,
  branch_node_id UUID,
  camera_id UUID, -- NULL until camera approved
  device_type TEXT,
  hardware_serial TEXT,
  manufacturer TEXT,
  model TEXT,
  mac_address MACADDR,
  current_ip_address INET,
  onvif_uuid TEXT,
  -- ... more fields
);
```

### 5. Frontend API Call
- **File**: `dashboard/components/device-manager.tsx`
- **Function**: `refreshBranch()` (line 423+)
- **API Call**: `cameraInventoryApi.listDiscovered(branchId)`
- **Endpoint**: `GET /v1/branches/:branchId/cameras/discovered`

### 6. Frontend Repository Query
- **File**: `src/database/edge-agent-repository.ts`
- **Method**: `listDiscoveries()` (line 571+)
- **Query**: 
  ```sql
  SELECT * FROM camera_discoveries
  WHERE branch_node_id = $1 AND status = 'pending'
  ORDER BY discovered_at DESC
  ```

### 7. Frontend UI Rendering
- **File**: `dashboard/components/device-manager.tsx`
- **State**: `discoveredCameras` (line 189)
- **Computed**: `discoveryQueueItems` (line 338) - maps discovered cameras to UI items
- **Display**: 
  - Shows count: "Found: X", "Pending: Y", "Approved: Z"
  - Lists cameras with "⚡ Approve & start live" button
  - Shows "No pending discoveries" if empty

## Key Status States

### `camera_discoveries.status`

| Status     | Meaning                                | Displayed in UI? |
|------------|----------------------------------------|------------------|
| `pending`  | Waiting for user review/approval      | ✅ Yes           |
| `approved` | User approved, camera provisioned     | ❌ No (archived) |
| `rejected` | User explicitly rejected this device   | ❌ No            |

### Discovery Lifecycle

```
Network Scan → Insert as 'pending' → User Reviews → Approve/Reject
                                           ↓              ↓
                                    'approved'      'rejected'
                                     (provision)      (archive)
```

## Re-Discovery Behavior

When the same camera is discovered again (same device_identity_id):

### OLD BEHAVIOR (BUG):
```typescript
// If camera was previously approved:
identity.cameraId ? "approved" : "pending"
// Result: status = "approved" → Not shown in UI
```

### NEW BEHAVIOR (FIXED):
```typescript
// Always reset to pending for user review:
status = "pending"
// Result: All re-discovered cameras appear in UI
```

### Conflict Resolution:
```sql
ON CONFLICT (branch_node_id, device_identity_id) DO UPDATE
SET status = CASE
  WHEN camera_discoveries.status = 'rejected' THEN 'rejected'
  ELSE 'pending'::discovery_status
END
```

**Rules**:
- ✅ Re-discovered cameras: Reset to `'pending'` for review
- ✅ Previously rejected: Stay `'rejected'` (don't bother user again)
- ✅ User must explicitly approve each time

## Common Issues

### Issue 1: "No pending discoveries" after successful scan
**Cause**: Status set to `'approved'` instead of `'pending'`
**Fix**: Set status to `'pending'` in createDiscovery() (see DEVICE_SCANNING_ONLINE_VIDEO_FIX.md)

### Issue 2: Duplicate cameras showing multiple times
**Cause**: device_identity_id changing on each scan
**Fix**: Improve identity resolution logic (MAC, serial, UUID matching)

### Issue 3: Edge agent offline
**Cause**: Agent not registered or network connectivity issue
**Fix**: Check edge_agents table status and last_ping_at
