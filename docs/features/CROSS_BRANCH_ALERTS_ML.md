# ക്രോസ്-ബ്രാഞ്ച് അലേർട്ട് വിസിബിലിറ്റി

## സംഗ്രഹം

ഇപ്പോൾ ഒരു യൂസറിന് അവർക്ക് ആക്സസ് ഉള്ള എല്ലാ ബ്രാഞ്ചുകളിൽ നിന്നുമുള്ള അലേർട്ടുകൾ കാണാൻ സാധിക്കും. മുമ്പ് ഒരു യൂസർക്ക് അവരുടെ അസൈൻ ചെയ്ത ബ്രാഞ്ചിലെ അലേർട്ടുകൾ മാത്രമേ കാണാൻ പറ്റുമായിരുന്നുള്ളൂ.

## മുമ്പും ഇപ്പോഴും - വ്യത്യാസം

### മുമ്പ്
- ഒരു യൂസർക്ക് **ഒരു ബ്രാഞ്ചിൽ** നിന്നുള്ള അലേർട്ടുകൾ മാത്രമേ കാണാൻ പറ്റൂ
- Regional/Zone മാനേജർമാർക്ക് ബ്രാഞ്ചുകൾക്കിടയിൽ സ്വിച്ച് ചെയ്യണം
- ഒന്നിലധികം ലൊക്കേഷനുകളിലെ അലേർട്ടുകൾ ഒരുമിച്ച് കാണാൻ പറ്റില്ല
- N ബ്രാഞ്ചുകൾ കാണാൻ N API കോളുകൾ വേണം

### ഇപ്പോൾ
- യൂസർക്ക് ആക്സസ് ഉള്ള **എല്ലാ ബ്രാഞ്ചുകളിൽ** നിന്നുള്ള അലേർട്ടുകൾ കാണാം
- ഒരു API കോൾ കൊണ്ട് ഒന്നിലധികം ബ്രാഞ്ചുകളുടെ അലേർട്ടുകൾ കിട്ടും
- ബ്രാഞ്ച് ഗ്രൂപ്പിങ്ങോടുകൂടിയ യൂണിഫൈഡ് ഡാഷ്ബോർഡ് വ്യൂ
- Regional/Zone/Area മാനേജർമാർക്ക് കൂടുതൽ സൗകര്യപ്രദം

## ആർക്കൊക്കെ പ്രയോജനം

| റോൾ | മുമ്പ് | ഇപ്പോൾ |
|------|--------|-------|
| **Super Admin** | എല്ലാ ബ്രാഞ്ചുകളും | എല്ലാ ബ്രാഞ്ചുകളും (മാറ്റമില്ല) |
| **Tenant Admin** | എല്ലാ ബ്രാഞ്ചുകളും | എല്ലാ ബ്രാഞ്ചുകളും (മാറ്റമില്ല) |
| **Regional Manager** | ഒരു സമയം ഒരു ബ്രാഞ്ച് | റീജിയനിലെ എല്ലാ ബ്രാഞ്ചുകളും |
| **Zone Manager** | ഒരു സമയം ഒരു ബ്രാഞ്ച് | സോണിലെ എല്ലാ ബ്രാഞ്ചുകളും |
| **Area Manager** | ഒരു സമയം ഒരു ബ്രാഞ്ച് | ഏരിയയിലെ എല്ലാ ബ്രാഞ്ചുകളും |
| **Branch Manager** | ഒരു ബ്രാഞ്ച് | ഒരു ബ്രാഞ്ച് (മാറ്റമില്ല) |
| **SOC Operator** | അസൈൻ ചെയ്ത ബ്രാഞ്ച് | അസൈൻ ചെയ്ത എല്ലാ ബ്രാഞ്ചുകളും |
| **Auditor** | ഒരു സമയം ഒരു ബ്രാഞ്ച് | സ്കോപ്പിലെ എല്ലാ ബ്രാഞ്ചുകളും |

## എങ്ങനെ ഉപയോഗിക്കാം

### API ഉപയോഗം

```bash
# ഒന്നിലധികം ബ്രാഞ്ചുകളിൽ നിന്നുള്ള അലേർട്ടുകൾ
GET /v1/ai/alerts?branchIds=branch-1,branch-2,branch-3

# എല്ലാ ബ്രാഞ്ചുകളിൽ നിന്നുള്ള അലേർട്ടുകൾ (അഡ്മിൻസിന്)
GET /v1/ai/alerts?tenantId=my-tenant

# ഒരു ബ്രാഞ്ച് മാത്രം (പഴയ രീതി - ഇപ്പോഴും പ്രവർത്തിക്കും)
GET /v1/ai/alerts?branchId=branch-1
```

### കോഡ് ഉദാഹരണം

```typescript
// ഒന്നിലധികം ബ്രാഞ്ച് ക്വറി
const alerts = await api.getAlerts({
  branchIds: user.branchScope, // ഉദാ: ["branch-1", "branch-2", "branch-3"]
  severity: 'P1',
  status: 'active',
});

// ബ്രാഞ്ച് അനുസരിച്ച് അലേർട്ടുകൾ ഗ്രൂപ്പ് ചെയ്യുക
const alertsByBranch = groupBy(alerts, 'branchId');
```

## പ്രധാന ഫീച്ചറുകൾ

✅ **ബാക്ക്വേഡ് കംപാറ്റിബിൾ** - നിലവിലുള്ള കോഡ് പ്രവർത്തിച്ചുകൊണ്ടിരിക്കും  
✅ **പെർഫോമൻസ് ഒപ്റ്റിമൈസ്ഡ്** - ഒന്നിലധികം ബ്രാഞ്ചുകൾക്ക് ഒരു ഡാറ്റാബേസ് ക്വറി മാത്രം  
✅ **ABAC എൻഫോഴ്സ്ഡ്** - യൂസർക്ക് ആക്സസ് ഉള്ള ബ്രാഞ്ചുകൾ മാത്രം കാണാം  
✅ **റിയൽ-ടൈം റെഡി** - WebSocket സബ്സ്ക്രിപ്ഷനുകളോട് ഒപ്പം പ്രവർത്തിക്കും  
✅ **മൊബൈൽ സപ്പോർട്ട്** - മൊബൈൽ ആപ്പുകളിൽ ലഭ്യം  

## സുരക്ഷാ മോഡൽ

### അധികാര പരിശോധന

1. **യൂസർ ഓതന്റിക്കേഷൻ**: യൂസർ ലോഗിൻ ചെയ്യുന്നു
2. **ബ്രാഞ്ച് സ്കോപ്പ് അസൈൻമെന്റ്**: യൂസർക്ക് ആക്സസ് ഉള്ള ബ്രാഞ്ചുകൾ അസൈൻ ചെയ്യപ്പെടുന്നു
   ```typescript
   user.branchScope = ["branch-1", "branch-2", "branch-3"]
   ```
3. **API അഭ്യർത്ഥന**: യൂസർ `branchIds` കൊണ്ട് അലേർട്ടുകൾ ആവശ്യപ്പെടുന്നു
4. **ABAC വാലിഡേഷൻ**: സിസ്റ്റം `branchIds ⊆ user.branchScope` എന്ന് പരിശോധിക്കുന്നു
5. **ഡാറ്റാബേസ് ക്വറി**: അധികാരമുള്ള ബ്രാഞ്ചുകൾ മാത്രം ക്വറി ചെയ്യപ്പെടുന്നു
6. **റെസ്പോൺസ്**: അധികാരമുള്ള ബ്രാഞ്ചുകളിൽ നിന്നുള്ള അലേർട്ടുകൾ തിരിച്ചയക്കുന്നു

## സാധാരണ പ്രശ്നങ്ങളും പരിഹാരങ്ങളും

### 1. അലേർട്ടുകൾ കാണുന്നില്ല

**ലക്ഷണങ്ങൾ**: API ശൂന്യമായ അറേ തിരിച്ചയക്കുന്നു

**സാധ്യമായ കാരണങ്ങൾ**:
- യൂസർക്ക് ബ്രാഞ്ച് സ്കോപ്പ് അസൈൻ ചെയ്തിട്ടില്ല
- യൂസറുടെ ബ്രാഞ്ച് സ്കോപ്പ് അഭ്യർത്ഥിച്ച ബ്രാഞ്ചുകളുമായി പൊരുത്തപ്പെടുന്നില്ല
- ആ ബ്രാഞ്ചുകളിൽ സജീവ അലേർട്ടുകൾ ഇല്ല

**പരിഹാരം**:
```typescript
// യൂസറുടെ ബ്രാഞ്ച് ആക്സസ് പരിശോധിക്കുക
console.log('User branch scope:', user.branchScope);

// API കോൾ വെരിഫൈ ചെയ്യുക
console.log('Requested branches:', branchIds);

// പൊരുത്തക്കേട് കണ്ടെത്താൻ ഇന്റർസെക്റ്റ് ചെയ്യുക
const accessible = branchIds.filter(id => 
  user.branchScope.includes(id)
);
console.log('Accessible branches:', accessible);
```

### 2. സ്ലോ ക്വറി പെർഫോമൻസ്

**ലക്ഷണങ്ങൾ**: API റെസ്പോൺസ് ചെയ്യാൻ >1 സെക്കൻഡ് എടുക്കുന്നു

**സാധ്യമായ കാരണങ്ങൾ**:
- ഡാറ്റാബേസ് ഇൻഡെക്സ് ഇല്ല
- വളരെയധികം ബ്രാഞ്ചുകൾ അഭ്യർത്ഥിച്ചിട്ടുണ്ട്
- ധാരാളം അലേർട്ടുകൾ

**പരിഹാരം**:
```sql
-- ഇൻഡെക്സ് ഉണ്ടോ എന്ന് പരിശോധിക്കുക
SELECT indexname FROM pg_indexes 
WHERE tablename = 'cameras' 
  AND indexname = 'idx_cameras_branch_node_id';

-- ഇല്ലെങ്കിൽ, സൃഷ്ടിക്കുക
CREATE INDEX idx_cameras_branch_node_id 
ON cameras(branch_node_id);
```

## പതിവ് ചോദ്യങ്ങൾ (FAQ)

**ചോദ്യം: ഇത് എന്റെ നിലവിലുള്ള കോഡ് തകർക്കുമോ?**  
ഉത്തരം: ഇല്ല. ഈ മാറ്റം ബാക്ക്വേഡ് കംപാറ്റിബിൾ ആണ്. ഒരൊറ്റ `branchId` ക്വറികൾ ഇപ്പോഴും പ്രവർത്തിക്കും.

**ചോദ്യം: ഡാറ്റാബേസ് മൈഗ്രേറ്റ് ചെയ്യണോ?**  
ഉത്തരം: ഇല്ല. സ്കീമ മാറ്റങ്ങൾ ആവശ്യമില്ല.

**ചോദ്യം: ഒറ്റ ബ്രാഞ്ച് ക്വറികൾ ഇപ്പോഴും ഉപയോഗിക്കാമോ?**  
ഉത്തരം: അതെ. `branchId` (ഒറ്റ) ഉം `branchIds` (ഒന്നിലധികം) ഉം രണ്ടും സപ്പോർട്ട് ചെയ്യുന്നു.

**ചോദ്യം: ഒരു യൂസർക്ക് ഏതൊക്കെ ബ്രാഞ്ചുകളിലേക്ക് ആക്സസ് ഉണ്ടെന്ന് എങ്ങനെ അറിയാം?**  
ഉത്തരം: `user.branchScope` അറേ പരിശോധിക്കുക. സൂപ്പർ അഡ്മിൻസിന് `["ALL"]` ഉണ്ടായിരിക്കും.

**ചോദ്യം: ഇത് മൊബൈൽ ആപ്പുകളെ ബാധിക്കുമോ?**  
ഉത്തരം: മൊബൈൽ ആപ്പുകൾക്കും അതേ API ഉപയോഗിക്കാം. മൾട്ടി-ബ്രാഞ്ച് ക്വറികളുടെ പ്രയോജനത്തിനായി അവ അപ്ഡേറ്റ് ചെയ്യുക.
